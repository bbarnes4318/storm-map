# Enrichment API — Production Safety Notes

## Why Mock Mode Is Blocked in Production by Default

The enrichment API returns **property data, homeowner contact information, and
financial credit transactions**. Mock mode generates fake data that could be
mistaken for real homeowner information. Exposing mock enrichment routes on a
public production server without safeguards creates several risks:

1. **Data confusion** — Fake property profiles (mock addresses, fake owners)
   could be mistaken for real data by users or downstream systems.
2. **Compliance liability** — Mock contact data (phone numbers, emails) could
   be used as if it were real, creating TCPA/DNC compliance violations.
3. **Credit fraud** — Mock credits are free and unlimited. Without gates, anyone
   could exercise the full unlock flow at no cost.
4. **Brand damage** — Serving obviously fake data to paying customers undermines
   trust in the platform.

## Required Environment Variables

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `ENRICHMENT_FEATURE_ENABLED` | Yes | `false` | Master kill switch. All routes return `503 FEATURE_DISABLED` unless `true`. |
| `ENRICHMENT_MOCK_MODE` | Yes | `true` | When `true`, uses in-memory mock stores and mock data providers. |
| `ENRICHMENT_ALLOW_MOCK_IN_PRODUCTION` | No | `false` | When `true` AND `NODE_ENV=production`, allows mock mode with a valid test token. |
| `ENRICHMENT_ADMIN_TEST_TOKEN` | Conditional | none | Required when mock mode is allowed in production. All requests must include `x-enrichment-test-token: <token>`. |
| `ENRICHMENT_ENCRYPTION_KEY` | Yes (prod) | none | 32-byte hex key (64 hex chars) for AES-256-GCM encryption of contact payloads. |
| `DATABASE_URL` | Yes (prod) | none | PostgreSQL connection string. Required when `ENRICHMENT_MOCK_MODE=false`. |

## How to Safely Test Mock APIs

### Local Development (recommended)

```bash
# .env.local
ENRICHMENT_FEATURE_ENABLED=true
ENRICHMENT_MOCK_MODE=true
# No other safety flags needed — NODE_ENV=development bypasses production gates
```

### Production Testing (gated)

```bash
# docker-compose.yml or server environment
ENRICHMENT_FEATURE_ENABLED=true
ENRICHMENT_MOCK_MODE=true
ENRICHMENT_ALLOW_MOCK_IN_PRODUCTION=true
ENRICHMENT_ADMIN_TEST_TOKEN=your-secret-random-token-here
ENRICHMENT_ENCRYPTION_KEY=<64 hex chars>
```

Then include the token header in every request:

```bash
curl -X POST https://your-server/storm-map/api/enrichment/attest \
  -H "Content-Type: application/json" \
  -H "x-enrichment-test-token: your-secret-random-token-here" \
  -d '{"agree":true}'
```

### Disabling enrichment entirely

Set `ENRICHMENT_FEATURE_ENABLED=false` (the default). All enrichment routes
will return:

```json
{
  "ok": false,
  "error": "FEATURE_DISABLED",
  "message": "The enrichment feature is not enabled on this server."
}
```

## Guard Decision Tree

```
Request → /api/enrichment/*
  │
  ├─ ENRICHMENT_FEATURE_ENABLED !== "true"
  │   └─ 503 FEATURE_DISABLED
  │
  ├─ NODE_ENV === "production" AND ENRICHMENT_MOCK_MODE === "true"
  │   │
  │   ├─ ENRICHMENT_ALLOW_MOCK_IN_PRODUCTION !== "true"
  │   │   └─ 403 MOCK_MODE_BLOCKED_IN_PRODUCTION
  │   │
  │   ├─ ENRICHMENT_ADMIN_TEST_TOKEN is not set
  │   │   └─ 403 MOCK_MODE_BLOCKED_IN_PRODUCTION
  │   │
  │   ├─ x-enrichment-test-token header missing or wrong
  │   │   └─ 403 INVALID_TEST_TOKEN
  │   │
  │   └─ Token matches → ALLOWED (mock mode, gated)
  │
  └─ All other cases → ALLOWED
```

> [!WARNING]
> Mock data is **NOT real homeowner data**. It is generated by the mock provider
> and includes fake names, fake phone numbers, and fake property records.
> Never present mock data to end users as real information.

## What Remains Before Production Launch

| Requirement | Status | Notes |
|-------------|--------|-------|
| PostgreSQL database | ❌ Not connected | Need DATABASE_URL + migrations |
| Drizzle migrations run | ❌ Not run | Schema exists, migrations not generated |
| Real authentication (Clerk/Supabase) | ❌ Mock only | All requests use mock account |
| Persistent credits | ❌ In-memory only | Lost on server restart |
| Stripe / credit purchase | ❌ Not started | No payment mechanism |
| Real data vendors (ATTOM, BatchData) | ❌ Mock only | Mock provider returns fake data |
| Rate limiting | ❌ Not implemented | API routes have no request limits |
| Audit logs persisted to DB | ❌ In-memory only | Lost on server restart |
| Transaction rollback tested | ❌ Not tested | Drizzle wrapper coded but unverified |
| OWNER_CONTACT encryption tested | ❌ Not tested | Only PROPERTY_PROFILE tested |

> [!CAUTION]
> **Do NOT set `ENRICHMENT_FEATURE_ENABLED=true` in production until ALL items
> above are resolved.** The feature flag exists specifically to prevent
> premature exposure of the enrichment system.
